# Market research — remote operations roles

Checked **20 November 2026**. Job adverts expire quickly; treat this as a
snapshot of requirement language, not a list of live openings.

The web-search tool was unavailable during this session (HTTP 402), so research
used two public job sources directly. No salary figure below is a promise to the
learner.

## Source 1 — Remote OK public API

URL: `https://remoteok.com/api?tags=operations`, retrieved 20 November 2026.
Remote OK requires attribution: this note names Remote OK as the source and
links back to it. No Remote OK logo is used.

The `operations` tag returned two listings. One was a COO role and is not a
target. The relevant one:

### Operations Expert with Python for AI Supply Chain Task Design — Toptal

URL: `https://remoteok.com/remote-jobs/remote-operations-expert-with-python-for-ai-supply-chain-task-design-toptal-1137690`
Location: anywhere in the world. Listed 5 November 2026.

Requirements stated in the advert:

- 3+ years hands-on supply chain or production planning work, not only studying,
  selling or managing it.
- Did the work within the last 3 years and can name the systems, tools, data and rules used.
- Personally executed a process where each case is decided by written rules — SOPs,
  planning rules or constraints.
- Worked inside systems of record such as ERP or WMS and with their exports or reports.
- Technical fluency in Python or another language and the command line, plus CSV/JSON,
  APIs or databases.
- Available to start around 4 November 2026.

Nice-to-have: automated or audited a process with scripts, SQL, RPA or a rules
engine; 5+ years in the same process family; Docker; Git; writing tests; SAP or
other ERP and TMS/WMS; advanced Excel.

Engagement: paid per task, about 60–75 minutes each, vetting task instead of a
live interview, reviewed by the client before approval.

**Fit notes.** The requirement language is unusually close to this portfolio:
written rules, edge cases, systems of record, Python, tests and Git. Two gaps
matter: the start date had already passed when checked, and ERP/WMS systems of
record are not evidenced in the portfolio. **Use this as a template for what to
look for, not as an application target.** The requirement "personally executed a
rule-driven process" is where the learner's FMCG and stores experience is
stronger than his automation portfolio.

## What the two sources agree on

1. Operations roles now ask for both process experience and the ability to
   automate or audit the process with scripts, SQL or a rules engine.
2. "Can name the systems, tools, data and rules used" is a recurring phrase.
   The learner should be able to say, for each portfolio project, exactly what
   the inputs, rules and outputs are.
3. Written tests and Git show up as differentiators even in non-engineering
   operations roles.
4. AI evaluation work is growing, but it usually needs a formal assignment and
   strict eligibility. It is a second-stage target, not the first application.

## Gaps the research exposes

| Gap | How to handle it |
|---|---|
| No named ERP or WMS system of record in the portfolio | Lead with the stores and route-sales experience; ask which system the role uses. Do not claim SAP. |
| HubSpot is marked learning | Do not apply to roles where HubSpot API is a hard requirement yet. |
| No scenario was built or run in Make during this work | Use the wording in `../DOCUMENTATION/make-verification.md`. |
| No paid client result | Offer a paid trial task. Do not invent a case study. |
| Employment dates missing from the CV | Confirm before sending any application. |
